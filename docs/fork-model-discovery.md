# 自用 fork：按供应商同步 Codex 模型

此 fork 在上游 CC Switch 3.20.4 的基础上补充模型发现的持久化，不修改 Claude 管理流程，也不把新模型映射成旧模型名。

## 使用

1. 编辑 Codex 的第三方供应商，上游格式选择 **Responses（原生）**。
2. 填好地址和密钥，点击 **拉取模型**。默认模型区和模型目录区的拉取按钮都支持同步。
3. 选择默认模型并保存供应商。拉取到的模型 ID 会单独保存在该供应商的 `settingsConfig.modelCatalog.discoveredModels` 中。
4. 切换供应商时，上游已有的事务写入流程会生成当前供应商的 `cc-switch-model-catalog.json`，并设置 `model_catalog_json`。Codex 已运行的进程可能需要重启后才重新读取。

每个供应商的数据保存在 CC Switch 数据库中；供 Codex 读取的目录文件仍沿用上游的单个活动文件。切回供应商会从它自己的数据重新生成，切换时无需访问远端。

## 刷新与手工配置

原则：**下载负责更新；优先级为手工映射 > 下载列表**（同名模型冲突时，手工映射优先）。

- 成功且非空的拉取结果替换该供应商上次发现的列表，所以已撤下的自动发现模型会在下次保存后移除。
- 超时、鉴权失败、空列表和过期请求不会清空上次列表。
- 手工模型配置与发现列表分开保存，同名时手工配置优先。
- 修改地址或密钥（包括原始配置编辑）会清空旧的发现列表，避免将另一条线路或另一个密钥的权限列表带过来。
- “清除自动发现列表”只清除自动发现部分，需保存后生效。
- OAuth 账号、Chat Completions 和 Anthropic 转换路径继续沿用上游行为；这里不启用后台轮询或每次切换联网拉取。

## 能力信息

New API 的 `/v1/models` 通常只有模型 ID。目录生成时会从本机 Codex 的 `models_cache.json` 查找**完全相同的 ID**，保留其工具、推理档位、上下文和模型指令。不会把别的模型的能力套给一个相似名称。

本机目录里不存在的模型使用保守模板：文本输入、不声明推理档位、上下文采用供应商配置或默认 128K。上游是否支持 Responses、工具调用以及声明的能力仍取决于供应商；模型出现在列表中不等于已完成推理可用性测试。需要时可用手工配置覆盖。

如果此前手工将 `model_catalog_json` 指向 `models_cache.json` 或其他文件，上游的配置保护机制会保留该指针。使用此功能前请备份并移除旧的手工指针，再重新应用供应商，让 CC Switch 管理目录。

## 构建与验证

`Fork Linux` 工作流运行相关前端测试、类型检查、Rust 目录与切换测试，并产出 Linux `.deb` 工件。首次 fork 若 Actions 未启用，需要在 GitHub Actions 页面启用工作流。它不发布 Release，不修改上游仓库。

自用构建仍沿用上游应用标识和数据目录，安装会替换现有版本；安装前备份 CC Switch 数据。上游更新功能仍指向官方更新源，使用自用版时不要安装官方更新覆盖它。

本地验证记录（2026-09-30）：前端相关测试、类型检查、前端构建、独立 Rust 目录测试通过；使用桌面捆绑的 Codex 0.159.0 在隔离目录调用 `model/list`，成功读取生成的 `gpt-6.1-sol` 和未知测试模型，没有发起推理请求。完整 Tauri 构建和数据库切换集成测试需由工作流验证（本机缺少 GTK/WebKit 开发库及对应 Rust 工具链）。
